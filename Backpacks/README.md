# Backpacks

Рюкзаки для Purpur/Paper 26.3: 17 тиров, крафт-цепочка, отдельный слот экипировки,
горячая клавиша и клиентский Fabric-мод с 3D-моделями.

## Что внутри

- **17 тиров** — от «Льняного мешочка» (9 ячеек) до «Абсолютного рюкзака» (256 ячеек).
- **Крафт-цепочка**: каждый следующий рюкзак крафтится из предыдущего, поэтому
  улучшение не теряет содержимое (UUID предмета сохраняется).
- **Упаковка в ячейке**: с 9-го тира одна ячейка держит до **27 стаков** одинаковых
  предметов (обычно 1728 штук). В GUI ячейка выглядит как один стак, общее количество
  видно в описании.
- **Экипировка без команд**: ЛКМ по слоту рюкзака в инвентаре (с модом), ПКМ по рюкзаку
  в инвентаре, Shift+ПКМ рюкзаком в руке. Клавиша из настроек (по умолчанию `B`) открывает
  надетый рюкзак; Shift+ПКМ пустой рукой или Shift+клавиша открытия снимают его. Слот
  рюкзака: ЛКМ берёт/кладёт рюкзак (в курсор или из курсора), ПКМ открывает.
- **Обычное окно рюкзака**: рюкзак открывается настоящим сундуком, поэтому всем клиентам
  (с модом и без) доступны обычные слоты Minecraft — ЛКМ/ПКМ, Shift+ЛКМ, цифры 1–9,
  Q / Ctrl+Q, двойной клик и перетаскивание. Рюкзаки до 45 ячеек открываются в сундуке
  подходящего размера, большие тиры — по 45 ячеек на страницу со стрелками в нижнем ряду.
  Pick-block (СКМ) в мире ищет предмет в надетом рюкзаке.
- **Детальные модели**: у каждого тира текстура 64×64 и модель на 22–44 элемента
  (карманы, уголки, стяжки, эмблема, скатка, подушки, замок, звезда). Свечения нет.
- **Хранение**: SQLite, привязка по UUID предмета, асинхронная запись + автосейв.
- **Мод**: клавиша, слот в инвентаре, 3D-рюкзак на спине (у каждого тира свой цвет)
  и необязательный handshake. Серверный ресурспак не нужен. Окно рюкзака — обычный
  сундук, поэтому мод его не рисует. Мод не вводит команды: клавиша отправляет
  `backpacks:open` (Shift+клавиша — `backpacks:unequip`), слот — `backpacks:slot`,
  вход — `backpacks:hello` и `backpacks:key`. Плагин отвечает только `backpacks:sync`
  (тир и два цвета для модели на спине).

## Требования

- JDK 25.
- Purpur/Paper 26.3 (api-version `26.3`).
- Fabric Loader 0.20.1 + Fabric API 0.166.2+26.3 для клиентского мода (опционально).

## Сборка

Нужен JDK 25; при первом запуске Gradle скачается сам (wrapper).

```bash
# Windows
gradlew.bat build

# Linux / macOS
./gradlew build
```

Готовые файлы:

- `plugin/build/libs/Backpacks-2.0.2.jar` — плагин (sqlite-jdbc внутри).
- `mod/build/libs/backpacks-mod-2.0.2.jar` — мод.

Ассеты мода (текстуры 64×64, 3D-модели, item definitions) генерируются скриптом
(Python 3 + Pillow):

```bash
python tools/gen_backpacks.py mod/src/main/resources
```

## Установка

1. Положить `Backpacks-2.0.2.jar` в `plugins/`.
2. Запустить сервер — создадутся `config.yml`, `messages.yml`, `backpacks.db`.
3. Мод `backpacks-mod-2.0.2.jar` — в `mods/` клиента (Fabric 26.3).
4. Без мода рюкзаки работают, но выглядят как базовый предмет без кастомной модели
   (музыкальная пластинка с PDC-меткой тира); с модом — как 3D-рюкзак.

## Сохранность содержимого

Содержимое рюкзака хранится не в предмете, а в `plugins/Backpacks/backpacks.db`
(SQLite); ключ — UUID в PDC предмета. Предмет носит только тир и этот UUID,
поэтому улучшение тира не теряет вещи.

- Запись: через 1 секунду после последнего клика в GUI, при закрытии, при выходе
  игрока, каждые 30 секунд и синхронно при остановке сервера.
- Открытие ждёт завершения очереди записи, поэтому «закрыл и сразу открыл» не
  откатывает изменения.
- Если база недоступна или данные не читаются, GUI не открывается: иначе
  закрытие пустого GUI перезаписало бы содержимое.
- Одно хранилище нельзя открыть двум игрокам одновременно (защита от копий
  предмета и старых общих стаков).
- SQLite в режиме WAL с `synchronous=FULL`: подтверждённые записи выдерживают
  сбой питания. Жёсткий сбой сервера может отнять максимум ~1 секунду
  изменений, сделанных после последнего клика.

Что может уничтожить сам **предмет** (содержимое останется в базе, но предмета
уже не будет): лава/огонь/пустота/кактус, `/clear`, плагины очистки,
`/bp remove`, а также смерть в лаве/пустоте при `keep-on-death: false`.
Поэтому периодически копируйте файл `backpacks.db` (лучше на остановленном
сервере; если копируете на живом — вместе с `backpacks.db-wal` и
`backpacks.db-shm`).

Все данные (конфиг, сообщения, база) лежат в `plugins/Backpacks/`, а не в jar:
удаление только `Backpacks-*.jar` ничего не теряет, удаление папки удаляет данные.

## Команды

| Команда | Право | Назначение |
| --- | --- | --- |
| `/bp` | `backpacks.use` | Открыть надетый рюкзак |
| `/bp recipes` | `backpacks.use` | Экран всех рецептов |
| `/bp equip` / `/bp unequip` | `backpacks.use` | Надеть / снять из руки |
| `/bp give <игрок> <тир> [кол-во]` | `backpacks.admin` | Выдать рюкзак (номер 1-17 или id) |
| `/bp remove` | `backpacks.admin` | Удалить рюкзак из руки вместе с содержимым |
| `/bp reload` | `backpacks.admin` | Перезагрузить конфиг и сообщения |

Право `backpacks.modbypass` — вход без мода при `require-mod: true`.

## Управление в GUI

- **ЛКМ** — взять/положить стак.
- **ПКМ** — взять/положить один предмет.
- **Shift+ЛКМ** по предмету в инвентаре — положить его в рюкзак (сначала в похожие ячейки, потом в пустые).
- **Цифры 1–9** — обменять ячейку с выбранным слотом хотбара.
- **Q / Ctrl+Q** — выбросить один предмет / стак.
- **Двойной клик** — собрать одинаковые предметы на курсор.
- **Перетаскивание** — разложить предметы по ячейкам.
- Для тиров 9+ (ячейка на 27 стаков): ЛКМ забирает стак, ПКМ — один предмет,
  Shift+ЛКМ — всё содержимое ячейки.
- Большие рюкзаки листаются стрелками в нижнем ряду; в центре — номер страницы.

## Слот рюкзака в инвентаре

- Значок рюкзака рядом с превью игрока, над слотом второй руки (слот рисует мод).
- Рюкзак в курсоре + ЛКМ по слоту — надеть; пустой курсор + ЛКМ — взять надетый рюкзак
  в курсор или надеть первый рюкзак из инвентаря.
- ПКМ по слоту — открыть надетый рюкзак.
- Без мода: ПКМ по рюкзаку в своём инвентаре надевает его, Shift+ПКМ пустой рукой снимает.
- Рюкзак во второй руке тоже работает: ПКМ открывает, Shift+ПКМ надевает.
  В чужих GUI (сундук и т. п.) ПКМ не перехватывается.
- Надетый рюкзак виден на спине игрока как 3D-модель; цвет корпуса и отделки
  берётся из тира и синхронизируется сервером для всех модовых клиентов.
- После перезахода сервер повторно присылает `sync` (сразу, через 20 и 60 тиков), поэтому
  слот и модель не пропадают.

## Книга рецептов

Все 17 рецептов регистрируются на сервере и автоматически открываются игроку при
входе, поэтому они видны в обычной книге рецептов Minecraft. Рецепт показывает
рюкзак предыдущего тира как ингредиент, но принимает любой рюкзак этого тира.

## Конфиг

```yaml
language: ru            # ru или en
equipment:
  keep-on-death: true   # оставлять надетый рюкзак после смерти
hotkey: NONE            # SWAP_HANDS = F без мода; NONE — выключить
open-empty-hand: true   # ПКМ пустой рукой открывает надетый рюкзак
require-mod: false      # кикать клиентов без мода
gui:
  sound-open: BLOCK_CHEST_OPEN
  sound-close: BLOCK_CHEST_CLOSE
  sound-click: UI_BUTTON_CLICK
  sound-upgrade: BLOCK_ANVIL_USE
autosave-seconds: 30    # автосохранение открытых рюкзаков
```

## Рецепты

Каждый тир требует рюкзак предыдущего тира плюс материалы (см. `/bp recipes`).
17-й тир: 2 звезды Нижнего мира, 2 кристалла Края, 2 незеритовых слитка,
1 драконье дыхание, 1 эндер-жемчужина и Драконий рюкзак.

Количества подобраны так, чтобы рецепт вместе с рюкзаком предыдущего тира
помещался в сетку 3×3: ванильный бесформенный рецепт допускает не больше
девяти ячеек с ингредиентами.

Рецепты бесформенные: лишние предметы в сетке не допускаются, лишние материалы
того же типа остаются в сетке.
